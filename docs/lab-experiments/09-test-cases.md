# Experiment 9: Test Case Design

**Experiment No:** 9
**Course Code:** 23CS4219
**Title:** Test Case Design for CCMS

## 1. Aim
To design comprehensive test cases for the Campus Complaint & Maintenance Management System (CCMS) using standard software testing techniques.

## 2. Objective
- To apply Black Box testing techniques such as Boundary Value Analysis (BVA) and Equivalence Partitioning (EP).
- To document functional, security, and role-based test cases for various modules of the application.
- To define clear pre-conditions, test data, steps, and expected outcomes.

## 3. Theory
Test case design is the process of generating tests that effectively validate software requirements. Key techniques include:
- **Equivalence Partitioning (EP):** Dividing input data into valid and invalid partitions. Test cases are designed to test one value from each partition.
- **Boundary Value Analysis (BVA):** Testing at the boundaries between partitions, as errors commonly occur at these edges (e.g., maximum file sizes, character limits).
- **Decision Tables:** Used for complex logic to test different combinations of inputs and corresponding actions (e.g., Role-based access control matrix).

## 4. Reference
The full set of 30 test cases covers Authentication, Complaint Submission, Tracking, Admin Verification, Assignment, Status Updates, Feedback, and Security.
